RESULT
------
The Wasm service sandbox executed on real AArch64 Redox inside QEMU. The run is
accepted only because the app declared success AFTER every assertion, which the
strict validator (scripts/qemu-demo/validate.sh) checked on the raw serial:

  SANDBOX_HELLO_OK                       (granted run completed)
  SANDBOX_REFUSED_TRACEEMIT              (refusal + stop reason, printed only
                                          after the re-entry assertion holds)
  stopped service is never re-entered  (the final refusal assertion ran)
  sandbox-demo: done                   (terminal: printed after every assertion)

A capture containing `sandbox-demo: FAIL`, or missing the terminal done line, is
rejected by the validator and produces no evidence at all.

The guest ran with NO network device: the firmware was loaded from a FAT ESP on
virtio-blk (bootindex=1), so there is no virtio-net and no TFTP. The UEFI line
"BdsDxe: starting Boot0001 ... from PciRoot(0x0)/Pci(0x2,0x0)" is that virtio-blk
device. Nothing in the RAM initfs starts a network daemon.

WHAT RAN
--------
apps/sandbox-demo (aarch64-unknown-redox ELF) links crates/sandbox (wasmi 2.0.0)
and embeds assets/hello_rs.wasm, whose digest is pinned in src/main.rs and is
checked against the freshly built guest by scripts/qemu-demo/check-digest.sh
before the cross-build is allowed to start. It is started by init as
45_sandbox_demo.service (oneshot, requires_weak 00_traced) from the
90_ramboot.target, and its stderr goes through logd to the kernel debug console.
Run 1 grants every capability; run 2 withholds trace.emit.

Note on the Loaded event: its `requested` list is what the module IMPORTS, not
what was granted — identical in both runs by design. The grants differ, which is
why run 2 ends in Denied { TraceEmit, NotGranted }.

NOT PROOF
---------
The host (x86_64) smoke run of the same app and the aarch64 rlib/ELF build are not
execution proof. Only the AArch64 Redox serial markers below count. And the
hashes below are receipts for run 20261025T054222Z-ccc1d9f6867a only: this build chain is not bit-
reproducible, so re-staging the same source yields different initfs/ESP/DTB
digests. Hashes identify a run; they do not prove two runs were identical.
