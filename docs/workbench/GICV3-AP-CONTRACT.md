## Accepted findings

- `src/arch/aarch64/device/irqchip/gic.rs`: `active()` requires GICD and GICC bases. Distributor `init()` populates the GICD base/capacity on the GICv3 parse path too; that does not initialize the GICv2 CPU interface. `send_sgi()` checks GICD, not `active()`, so a blanket claim that every GICv3 send returns before MMIO is false.
- `irqchip/mod.rs::init_ap()` currently admits only the GICv2 path. GICv3 AP activation is not implemented. `cpu/boot.rs` initializes local interrupt state before the generic timer and parks on failure.
- The pure `gicv3/model.rs::sgi1r_for_affinity()` encoder already exists and rejects unsupported Aff0 instead of changing directed intent to broadcast. Adding an unused wrapper is not completion of a missing production sender.
- The W1C distributor defect is already fixed by canonical patch0023. The 23-patch image has accepted generic-QEMU 1CPU protocol evidence; this is not SMP proof.

## Corrections required before implementation

1. **Ownership before mutable access.** `GicV3::rd_registry` is one per-controller `RdRegistry { entries: Vec<(u32, usize)> }` spanning CPU affinities. It is shared software state, not one registry per CPU. `init_current_rd(&mut self)` mutates it; lookup also accesses that shared object. Hardware-banked redistributors/system registers do not remove Rust aliasing obligations. Existing `irqchip/mod.rs::acknowledge_root()` constructs a mutable controller reference through global `IRQ_CHIP`, and `end_root()` accesses that controller too. A future SMP design must establish serialization or remove shared mutable access **before** concurrent mutable references are constructed; a lock only around Vec insertion is insufficient. Review interrupt reentrancy and lock order as well as AP initialization. Current single-CPU evidence does not reproduce an SMP failure.
2. **Conditional group programming.** `model::init_private()` always wakes/disables the private interrupts and sets priorities, but writes GICR_IGROUPR0/IGRPMODR0 only when `GICD_CTLR_DS` is set. Otherwise firmware group configuration is preserved. Do not describe every path as forcing Group1NS.
3. **Complete AP dependency contract.** Before removing the AP gate, specify root-controller selection, RD discovery and publication, banked local enable/acknowledge/EOI, timer/SGI enabling order, directed target representation in boot slots/per-CPU state, and failed-init rollback. Keep explicit error returns for unsupported directed targets; broadcast is separate intent.
4. **Evidence scope.** Pure host models can validate register writes and target encoding, but cannot prove absence of production aliasing or AP liveness. Require production-path ownership review and separately admitted multi-CPU runtime proof. Neither the previous single-CPU protocol gate nor a future SMP emulator result is physical-phone proof.

The next gate is a corrected ownership/local-IRQ/caller design with actual production call sites and meaningful acceptance criteria. No new kernel patch, wrapper, AP enable, MMIO operation, VM phase or phone operation is authorized by this review. The unverified exact Arm document reference in the native proposal is not adopted here; these findings are grounded in the named source and existing regression receipts.

### IRQ-mask audit correction

AARCH64-IRQ-MASK-AUDIT.md was delivered but its architectural conclusions are NOT accepted. Absence of explicit DAIF instructions in the entry stub does not imply an unknown or unmasked exception-entry state. Saving SPSR preserves the saved PSTATE including its DAIF masks; ERET restores PSTATE. Consequently the artifact's statements that the masks are not captured/restored, or that IRQ nesting is bounded only by GIC priority, are incorrect. The immediate selector #2 controls the IRQ I field, not D. Source references to raw shared accesses and lack of an IRQ_CHIP mutex remain useful, but cannot alone diagnose single-CPU reentrancy. Trace any subsequent explicit unmask/scheduling/blocking path before declaring per-site coverage; exception entry masking alone also does not prove complete lifetime coverage or SMP safety.

Primary architecture reference: [Arm AArch64 Exception Model 102412_0103_02_en](https://documentation-service.arm.com/static/67ac57fb091bfc3e0a9479cc), printed pp27–28 (PSTATE/SPSR/ERET) and p38 (explicit re-enabling needed for nested interrupts). No new kernel defect or runtime failure is established by the rejected mask audit.

Independent Luna follow-up also excludes profiling.rs:424 from AArch64 mask transitions: it is behind target_arch=x86_64 at :401-402. CleanLockToken at sync/ordered.rs:157-181 tracks no acquired locks and lock ordering; it does not mask IRQs. No AArch64 exception-handler explicit IRQ re-enable was found in the reviewed paths. The raw static graph remains an SMP ownership obligation, but neither report proves a new single-CPU interrupt race. Accepted per-site conclusions remain limited to reviewed direct source observations; no runtime result or global safety proof is claimed.
