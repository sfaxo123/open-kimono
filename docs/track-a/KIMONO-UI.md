# Kimono UI ↔ agentd contract (Track A2)

The kimono view (`apps/kimono-ui`) and the agent daemon (`apps/agentd`, Lane 1)
coordinate **only** through the `trace-events` schema. This file records the
transport shape the UI consumes so Lane 1 does not have to guess.

## `GET /events` — Server-Sent Events of journal records

One journal record per SSE frame:

```
id: <envelope seq>
data: {"seq":0,"ts_us":1762100000000000,"service":"agentd","trace_id":"…32 hex…","span_id":"…16 hex…","payload":{"kind":"ag_ui","type":"RUN_STARTED",…}}

```

Rules the UI depends on:

1. `data:` is **exactly one** `trace-events` JSONL record — no wrapping object,
   no array, no prefix.
2. `id:` is the envelope `seq`, as a decimal integer. The browser sends
   `Last-Event-ID` on reconnect; the server must resume with the first record
   whose `seq` is greater than it.
3. Frames are separated by a blank line; a frame may not span multiple `data:`
   lines (the UI does not concatenate them).
4. `Content-Type: text/event-stream; charset=utf-8`, `Cache-Control: no-store`.
5. Bind to `127.0.0.1` or the phone's Meshnet address only (PLAN phone-safety rule).

The UI never invents records: a frame it cannot parse becomes a visible
`journal line rejected: …` banner, and a record whose envelope is off-schema
(bad `seq`, non-hex `trace_id`/`span_id`) becomes an `UNHANDLED envelope/…`
item. Silence is a bug.

## `POST /request` — the ask box and the service stop buttons

```
POST /request  {"text":"remind me every 2 minutes to drink water"}  -> 202 {"ok":true,"runId":"…"}
```

- 400 with a JSON `{"error":"…"}` naming the offending field when `text` is
  missing, empty, not a string, or longer than 500 characters.
- The UI does not render the request itself; it waits for the journal
  (`RUN_STARTED` + `TEXT_MESSAGE_*` with `role:"user"`), so the request is
  visible even when it arrives by voice.

## Serving the page

agentd may serve `apps/kimono-ui/web/` at `/` (`index.html`, `app.js`,
`render.mjs`, `dom.mjs`, `style.css`). The page references no external
origin, so it works with the phone offline. `apps/kimono-ui/server.mjs` is a
dev-only replay stand-in, not something to ship.

Verified against the real agentd (2026-11-02, `static_dir` set to this `web/`
directory): `GET /` → 200 `text/html` 1084 bytes, `GET /events` sends `id:` =
`seq` for every frame, and `Last-Event-ID: 5` resumes at `seq 6`. The journal
of a real gateway run is in `docs/track-a/evidence/A2-real-agentd-sse.trace`
(14 records, answer `108`); all 14 render with zero unhandled records.

### Two things the real agentd does differently
1. **`POST /request` answers synchronously.** It returns
   `{"answer":"108","brain":"homelab-gateway","error":null,"run_id":"…"}`
   rather than a bare 202. Consumers must not assume the answer is only
   reachable through the journal — but reading it from the journal is still
   what keeps voice and screen in agreement, so `voiced` keeps tailing.
2. **The user's request is not journalled.** A real run writes 14–24 records
   and none of them is a `TEXT_MESSAGE_*` with `role:"user"`, so the kimono
   shows the answer but never what was asked, and a consumer cannot correlate
   an answer to its request by text. `voiced` works around it by resuming the
   stream after the `GET /health` event count and says so in its own journal.
   The fix belongs in agentd: journal the request as
   `TEXT_MESSAGE_START(role:"user") / CONTENT / END`.

### What the stop buttons actually do

agentd exposes four routes: `/health`, `/events`, `POST /request`, and the
static page. There is no `/service/stop`. So the page's stop buttons send a
natural-language request — `stop the <name> service` — through `POST /request`
and let the agent act, which keeps one authority over services instead of
giving the browser a privileged door. On the phone the effect is currently
*recorded, not performed* (Lane 1's L1-D8: `RecordingHost` journals
`svc.effect_requested` with `dry_run: true`), so a press shows up in the feed as
a requested effect rather than a service that disappeared. That is the honest
behaviour today, and the view does not pretend otherwise.

## Fixtures

`apps/kimono-ui/fixtures/*.jsonl` are generated by `kimono-fx` from the
`trace-events` types, so they cannot drift from the schema:

| fixture | what it exercises |
| --- | --- |
| `water_reminder` | the PLAN demo sentence: create → run → stop a service, grants, state |
| `fallback_failure` | gateway timeout → announced local fallback → malformed tool-call args → `RUN_ERROR` → dropped journal records |
| `voice_mic_power` | mic lifecycle, STT partial/final, cleaned text, wake locks, power, service + grant lifecycle |
| `vocab_coverage` | every AG-UI type, every `gen_ai` operation, interrupts, subagents, snapshots and deltas |

Regenerate with `cargo run` in `apps/kimono-ui`; `cargo run -- --check` fails
if the checked-in fixtures are stale.
