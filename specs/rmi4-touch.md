# OnePlus 6 RMI4 touch subset (K9)

The OnePlus 6 DT names `syna,rmi4-s3706b` at i2c12 address 0x20, with TLMM GPIO 125 falling-edge IRQ, 200 ms reset/startup delays, F01 nosleep, and F12 clip-x-high 1079. Power rails are `vreg_l28a_3p0` and `ts_1p8_supply`. No reset, rail, or pin writes belong in the initial read-only driver.

RMI4 pages contain a Page Descriptor Table from 0xe9 down in 6-byte entries: query, command, control, data, interrupt-source count, function number. Find F01 and F12; reject missing/duplicate functions and page/offset overflow. F01 status/IRQ byte must be sampled before a touch report. F12 Data1 object reports contain 8 bytes per slot: status/object type, X low/high, Y low/high, Z, width X/Y. F12 register-descriptor queries determine the Data1 offset and slot count; do not hardcode either for hardware. Until an oracle capture supplies those query bytes, host tests use an explicit descriptor fixture and the production daemon must fail closed. Emit only finger contacts within the clipped X range, and release on an empty frame. Multi-touch slot to `inputd` mapping remains a separate acceptance gate because OrbClient's generic pointer event is single-pointer.
